Prepared for Srikanth Kamuni. Work through Excel first, then SQL, then Python. The same definitions and clean sales lines are used throughout, so differences between tools can be investigated rather than guessed.

What is real, and what is simulated?

data/puma_published_sales_2023_2024.csv contains a small extract of published PUMA Group sales. The source is PUMA Annual Report 2024, “Sales development”: https://annual-report.puma.com/2024/en/combined-management-report/economic-report/sales-development/index.html. These are historical figures, not a claim to be the latest report.

Published group sales were EUR 8,601.7 million in 2023 and EUR 8,817.2 million in 2024. The 2024 regional figures are EMEA 3,475.7, Americas 3,536.0 and Asia/Pacific 1,805.5, all in EUR million. The 2024 product-division figures are Footwear 4,733.6, Apparel 2,813.9 and Accessories 1,269.7, also in EUR million. The reporting-currency growth calculation is approximately 2.5%; the report's 4.4% currency-adjusted growth is a different measure.

All remaining data is simulated for learning, including countries, customers, product names, prices, discounts, costs, deliveries and targets. It is not PUMA's internal transaction data, not a representative sample of that data, and not scaled to match its reported turnover. Product names beginning with “Practice” are invented. There are no actual customer details. The project covers 12 selected countries; it does not contain every market in which PUMA operates.

The published reference has three alternative views of sales: group, region and product division. Do not sum all rows together. Doing so counts the same underlying sales repeatedly. Keep the real-data exercise separate from the simulated dashboard.

The business assignment

You are preparing a sales review for a practice sportswear business. Management wants to know how sales and gross profit changed from 2023 to 2024, which regions and categories contribute most, whether sales meet monthly regional targets, and how returns, discounts and shipping affect results. Your final deliverables are an Excel dashboard, a set of SQL reports and a reproducible Python analysis with charts.

The dataset has 7,200 lines, 3,600 placed orders, 900 customer-dimension records, 24 practice products, 12 countries, three regions, three categories and three channels. It covers January 2023 through December 2024. There are exactly 150 orders in each month and two product lines in each order. This controlled structure makes validation easier; it is not a realistic estimate of PUMA's transaction volume. Not every customer-dimension record necessarily has an order.

Metric definitions and assumptions

The project ignores VAT, foreign-exchange conversion, operating expenses, damaged-return losses and return-processing fees. All money inputs are already simulated EUR. Refunds use the original discounted unit price. Returned units are assumed to be recoverable, so their cost is removed from recognised COGS. Returns are attached to the original order and original month; no separate return date is available. Consequently, this is a teaching model for sales analysis, not a complete accounting revenue-recognition system.

Round individual money components to two decimals, then aggregate them. Store rates as fractions. Do not average margin percentages to produce an overall margin. Do not divide returned units by net units when calculating the defined unit return rate.

FirstOrderFlag works for the supplied dashboard's year and region filters because both lines of an order share those attributes. It is unsafe for a product or category filter: the flagged line might be in a different category from the remaining line. In those reports use a distinct OrderID count, an order-level table, or Excel's Data Model distinct count.

5. Calculate revenue in visible steps

  1. In V1 type GrossSalesEUR. In V2 type =ROUND(K2*L2,2). Quantity in K2 multiplied by unit price in L2 gives the original selling value. ROUND(...,2) keeps cents.
  2. In W1 type DiscountEUR. In W2 type =ROUND(V2*M2,2). A discount rate of 0.20 means 20% of the gross value. Do not multiply by 20.
  3. In X1 type SalesAfterDiscountEUR. In X2 type =V2-W2. This is the amount after the price discount but before refunds.
  4. In Y1 type RefundEUR. In Y2 type =ROUND(N2*L2*(1-M2),2). Returned units are refunded at the original discounted price. Parentheses calculate the fraction of price retained after the discount.
  5. In Z1 type NetSalesEUR. In Z2 type =X2-Y2. This is the net sales amount retained by the business.
  6. Ensure V2:Z7201 are filled. Select that range, press Ctrl+1 and choose Currency with the euro symbol and two decimal places. The data is already EUR; this is display formatting, not currency conversion.
  7. Check one row by hand. Multiply its units by price, calculate its discount, subtract the refund and compare with Z. Use a row with ReturnedQty greater than zero as well as one with no return.
  8. The formulas are deliberately split into components. If net sales is wrong, inspect quantity, price, discount and refund separately. A single long formula would hide the point where the error occurs.

6. Calculate retained units, COGS and profit

  1. In AA1 type NetUnits. In AA2 type =K2-N2. This counts the units customers kept.
  2. In AB1 type COGSEUR. In AB2 type =ROUND(AA2*O2,2). O contains unit cost at sale. Under the practice model, returned units reverse their cost.
  3. In AC1 type GrossProfitEUR. In AC2 type =Z2-AB2. Gross profit excludes operating expenses.
  4. In AD1 type ContributionEUR. In AD2 type =AC2-P2. This subtracts the line's allocated outbound shipping cost. It does not include salaries, rent, marketing or tax and must not be labelled net profit.
  5. In AE1 type Margin. In AE2 type =IF(Z2=0,"",AC2/Z2). IF evaluates a condition. If net sales is zero, display blank because a line margin is undefined. Otherwise divide gross profit by net sales.
  6. In AF1 type ReturnFlag. In AF2 type =IF(N2>0,1,0). It returns 1 for a line with any returned units and 0 otherwise. It counts returned lines, not returned units.
  7. Fill AA:AF through row 7201. Format AB:AD as EUR and AE as Percentage with one decimal. Format AA and AF as whole numbers.
  8. Click a data cell and open Table Design → Resize Table. Confirm the Table is Sales!$A$1:$AF$7201. These calculations must be inside SalesData for the structured formulas below to recognise their names.
  9. Click AE2. Inspect the formula bar and then click AE7201. The row references should move. A formula such as =$AC$2/$Z$2 copied down would incorrectly use the first line's margin for every row.

7. Learn a lookup without replacing transaction costs

  4. Restore AH8 to P001. Use this exercise to learn mapping. Do not replace the stored transaction unit costs with today's product cost in a historical report; that would change the meaning of historical profit.

9. Calculate dashboard headline metrics

  1. In B6 type Net sales (EUR). In B7 enter:
=SUMIFS(SalesData[NetSalesEUR],SalesData[Year],$B$3,SalesData[Region],IF($B$4="All","*",$B$4))

SUMIFS adds the first range only for rows meeting every subsequent criteria pair. The first pair chooses the year; the second chooses the region. The result for 2024 and All is 1,885,059.75.

  1. In E6 type Gross profit (EUR). In E7 enter:
=SUMIFS(SalesData[GrossProfitEUR],SalesData[Year],$B$3,SalesData[Region],IF($B$4="All","*",$B$4))
  1. In H6 type Gross margin. In H7 type =IF(B7=0,"",E7/B7). This is total gross profit divided by total net sales. Do not use AVERAGE(SalesData[Margin]) to produce this KPI.
  2. In K6 type Placed orders. In K7 enter:
=SUMIFS(SalesData[FirstOrderFlag],SalesData[Year],$B$3,SalesData[Region],IF($B$4="All","*",$B$4))

The result is 1800 for 2024 and All. FirstOrderFlag is safe under these year/region filters. If you later add category filters, rebuild the order count using distinct OrderID values.

  1. In B8 type Unit return rate. In B9 enter:
=SUMIFS(SalesData[ReturnedQty],SalesData[Year],$B$3,SalesData[Region],IF($B$4="All","*",$B$4))/SUMIFS(SalesData[Quantity],SalesData[Year],$B$3,SalesData[Region],IF($B$4="All","*",$B$4))

Every supplied year/region combination has sold units, so the denominator is positive. For a report with potentially empty selections, test the matching sold-unit total before dividing. Do not hide all errors with IFERROR(...,0).

  1. In E8 type Average order value (EUR). In E9 type =IF(K7=0,"",B7/K7).
  2. In H8 type Contribution (EUR). In H9 enter:
=SUMIFS(SalesData[ContributionEUR],SalesData[Year],$B$3,SalesData[Region],IF($B$4="All","*",$B$4))
  1. In K8 type Net sales YoY. In J10 enter the prior-year total as a visible supporting calculation:

  2. Format B7, E7, E9 and H9 as EUR. Format H7, B9 and K9 as percentages. Format K7 as a whole number. Use one decimal for rates, and two decimals for detailed money values.

2. Understand the relational structure

orders is the order header. It owns OrderDate, CustomerID, Country, Channel and PaymentMethod. order_lines owns Quantity, UnitPriceEUR, DiscountRate, ReturnedQty, UnitCostEUR, ShippingCostEUR and DeliveryDays. There are two lines for each order. products adds names and categories. countries adds region. customers adds segment and signup year. monthly_targets has one row per MonthStart and Region.

A primary key uniquely identifies a row. Orders has OrderID; order_lines has LineID. A foreign key expresses a relationship, such as order_lines.OrderID referencing orders.OrderID. In SQLite, foreign-key enforcement is connection-specific, so run PRAGMA foreign_keys=ON; when writing data. A composite key contains more than one field: monthly_targets uses MonthStart and Region together.

The supplied schema has NOT NULL and CHECK constraints. NOT NULL requires a value. CHECK restricts acceptable values, such as a positive Quantity and ReturnedQty no greater than Quantity. These constraints protect the clean loaded tables; they do not replace quality investigation on untrusted raw input.

This schema uses REAL money fields for a beginner-readable project and rounds line-level components to cents. REAL is floating point, so sums can have tiny residues. Compare money with a 0.01 EUR tolerance. For production financial storage, consider integer minor units or a database with suitable fixed-decimal types and an agreed rounding policy.

4. Understand the reusable views before the reports

Run this setup exactly as supplied:

-- Run once on puma_starter.sqlite before the analytical queries.
CREATE VIEW IF NOT EXISTS v_base AS
SELECT l.*, o.OrderDate, o.CustomerID, o.Country, o.Channel,
       o.PaymentMethod, p.ProductName, p.Category, c.Region,
       CAST(strftime('%Y',o.OrderDate) AS INTEGER) AS Year,
       substr(o.OrderDate,1,7)||'-01' AS MonthStart,
       ROUND(l.Quantity*l.UnitPriceEUR,2) AS GrossSalesEUR,
       ROUND(l.Quantity*l.UnitPriceEUR*l.DiscountRate,2) AS DiscountEUR,
       ROUND(l.ReturnedQty*l.UnitPriceEUR*(1-l.DiscountRate),2) AS RefundEUR,
       l.Quantity-l.ReturnedQty AS NetUnits,
       ROUND((l.Quantity-l.ReturnedQty)*l.UnitCostEUR,2) AS COGSEUR
FROM order_lines AS l
JOIN orders AS o ON l.OrderID=o.OrderID
JOIN products AS p ON l.ProductID=p.ProductID
JOIN countries AS c ON o.Country=c.Country;

CREATE VIEW IF NOT EXISTS v_net AS
SELECT *, ROUND(GrossSalesEUR-DiscountEUR-RefundEUR,2) AS NetSalesEUR
FROM v_base;

CREATE VIEW IF NOT EXISTS v_sales AS
SELECT *, ROUND(NetSalesEUR-COGSEUR,2) AS GrossProfitEUR,
       ROUND(NetSalesEUR-COGSEUR-ShippingCostEUR,2) AS ContributionEUR
FROM v_net;

CREATE INDEX IF NOT EXISTS idx_orders_date ON orders(OrderDate);
CREATE INDEX IF NOT EXISTS idx_lines_order ON order_lines(OrderID);
CREATE INDEX IF NOT EXISTS idx_lines_product ON order_lines(ProductID);

The FROM clause starts with product lines. Each JOIN supplies a single matching descriptive row or order header. The join should preserve all 7,200 clean lines. v_base extracts date keys and calculates gross sales, discount, refund, net units and COGS. v_net subtracts discount and refund to calculate net sales. v_sales calculates gross profit and contribution. Splitting these into layers avoids trying to reuse a new alias within the same SELECT list and makes intermediate values inspectable.

IF NOT EXISTS makes repeated setup safe for existing views and indexes. It does not update a view definition if you edit the file later; to change a definition deliberately, drop and recreate that view in your working database. Indexes organise access to keys and dates. They can help suitable filters and joins but use storage and add write overhead. Do not create indexes merely because a column exists.

5. A query's written order and logical work

Write most queries in this order: WITH, SELECT, FROM, JOIN/ON, WHERE, GROUP BY, HAVING, ORDER BY, LIMIT. As a useful beginner model, the database first forms the source and joins, filters rows with WHERE, forms groups, applies aggregate calculations and HAVING, calculates selected output and windows, then sorts and limits. Optimisers may choose a different physical execution strategy while preserving the requested result.

Use WHERE for line-level or order-level conditions before aggregation. Use HAVING for conditions on group totals. Put grouped descriptive fields in GROUP BY rather than relying on SQLite's allowance for bare columns in aggregate queries. When using aliases, qualify ambiguous source fields with table names or short table aliases.

7. Practise UPDATE and transaction rollback safely

The reporting queries are read-only. The following exercise changes a temporary practice table, not the sales or original target table. Open sql/03_transaction_practice.sql. For visible before/after results, execute the statements one at a time rather than the whole script in one click.

-- Use a temporary table so source tables remain intact.
CREATE TEMP TABLE practice_targets AS SELECT * FROM monthly_targets;
BEGIN TRANSACTION;
UPDATE practice_targets SET TargetNetSalesEUR=ROUND(TargetNetSalesEUR*1.05,2)
WHERE MonthStart='2024-01-01' AND Region='EMEA';
SELECT * FROM practice_targets WHERE MonthStart='2024-01-01';
ROLLBACK;
SELECT * FROM practice_targets WHERE MonthStart='2024-01-01';
DROP TABLE practice_targets;
  1. Run CREATE TEMP TABLE. AS SELECT copies the target rows into a temporary table for this connection. It does not inherit all original constraints.
  2. Run BEGIN TRANSACTION. This starts a unit of work whose changes can be kept or rolled back.
  3. Run UPDATE. SET changes the artificial target by 5% only for the specified month and region. The WHERE clause limits the change. Without WHERE, every row in the temporary table would change.
  4. Run the first SELECT. Compare the EMEA January 2024 target with the original table.
  5. Run ROLLBACK. It reverses the UPDATE because the change was inside the transaction. The temporary table remains because its creation occurred before BEGIN.
  6. Run the second SELECT. The original value should be restored. COMMIT would keep the change; it is deliberately not used in this exercise.
  7. Run DROP TABLE practice_targets. DROP removes the temporary table definition and its rows. Do not substitute an original source-table name.

2. Learn the syntax before the data analysis

Python assigns a value with =. For example, year=2024 creates a variable. Equality testing uses ==, not =. Text is written inside quotes, such as 'Poland'. A list groups values in order, such as ['Country','NetSalesEUR']. A dictionary maps names to values, such as {'year':2024}. Parentheses call functions and methods. Square brackets select elements or DataFrame columns.

import pandas as pd loads a library and gives it the short name pd. pd.read_csv(...) is a library function. sales.head() is a method operating on the sales object. A DataFrame is a table of columns and rows; a Series is a single column-like sequence. Names such as sales and monthly are variables containing those objects, not filenames or SQL tables.

A comment starts with #. A line ending in : opens an indented block, such as a loop, function or with statement. Keep the four-space indentation used in the supplied code. Missing pandas data commonly appears as NaN or NaT. NaT is a missing date. .isna() identifies missing values. NaN is not a numeric zero, and replacing it with zero changes the meaning of the data. A missing discount is unknown until a source rule resolves it.

An assert statement checks a condition and stops execution if it is false. It is useful here for learning and reproducible checks. It does not repair data. Do not disable assertions during this practice project. Production input validation usually needs explicit error handling and logs as well.
